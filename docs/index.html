claude-profile

Use a second Claude Code login next to your first, say a personal account in one terminal and a work account in the other. Both keep the same settings, plugins and history.

Legal use only

Use claude-profile only with Claude accounts you own or are authorized to use, and only in ways your Anthropic plan's terms allow. It does not share, pool or resell access. Don't use it to let other people use your account, or to get around usage limits or other protections.

Install and set up a profile

curl -fsSL https://raw.githubusercontent.com/agentic-tool-labs/claude-profiles/main/install.sh | sh

The installer puts claude-profile in ~/.local/bin. Set CLAUDE_PROFILES_BIN first to install it somewhere else. If you'd rather read the script before running it, it's 20 lines.

claude-profile add work      # creates the claude-work command
claude-work                  # type /login and sign in with the other account
claude-profile doctor work   # checks the two logins are separate

After that, claude is your main account and claude-work is the other. You can run them in two terminals at the same time.

What's shared and what isn't

Shared

Everything in ~/.claude and ~/.claude.json: settings, plugins, skills, hooks, CLAUDE.md, MCP servers, project trust and session history. Change a setting in one terminal and the other sees it.

Separate

The login. Each command sends inference, usage, billing and Remote Control to the account it is signed in to.

How it works

claude-work is a short wrapper that runs your usual claude with CLAUDE_SECURESTORAGE_CONFIG_DIR set to ~/.claude-profiles/work. That variable changes where Claude Code stores the login and nothing else. On macOS the login goes in its own Keychain entry, named Claude Code-credentials- plus the first 8 hex digits of the folder path's SHA-256. On Linux and Windows it goes in ~/.claude-profiles/work/.credentials.json instead of ~/.claude/.credentials.json.

The documented CLAUDE_CONFIG_DIR also gives you a second login, but it moves your settings, plugins and history along with it, so the two accounts end up with separate setups.

Commands

claude-profile add <name>
Creates claude-<name> in ~/.local/bin and a private folder for its login. It won't overwrite a command it didn't create, and profile is reserved.
claude-profile list
Lists the profiles this tool created.
claude-profile doctor <name>
Checks the Claude Code version, that this build supports the variable, that the profile has its own stored login, and that the login belongs to a different account from claude.
claude-profile remove [-y] <name>
Deletes claude-<name> and the login stored for it. Your main login is never touched.

CLAUDE_PROFILES_HOME and CLAUDE_PROFILES_BIN change where profiles and commands go.

To find out which account a login belongs to, doctor sends its access token to api.anthropic.com/api/oauth/profile. The token reaches curl on standard input, so it never appears in a process list.

Caveats

The variable is undocumented

CLAUDE_SECURESTORAGE_CONFIG_DIR is internal to Claude Code, and a future release could rename or remove it. If that happens, running /login in a profile would replace your main login. add refuses a Claude Code build that doesn't contain the variable, and deletes the new command again if it reports a login before you've signed in. Run claude-profile doctor <name> after each Claude Code update.

Tested on macOS only

It has been run on macOS with Claude Code 2.1.330. Linux and Windows support comes from reading Claude Code's source and hasn't been tried. The wrapper is a POSIX shell script, so Windows needs WSL or Git Bash.

/status can show the wrong account

/status reads oauthAccount from the shared ~/.claude.json, and so does the account email Claude Code tells the model. That field names whichever account logged in most recently. Inference, usage limits and Remote Control use each command's own login and are unaffected. claude-tui-line 0.8.0 and later have email and organization status-line items that show each session's real account.

Removing a profile

claude-profile remove work

After you confirm, it deletes claude-work, that profile's Keychain entry or credentials file, and its folder if the folder is empty. -y skips the confirmation.
