claude-profile

Run more than one Claude Code login at the same time, for example a personal account in one terminal and a work account in another, with your settings, plugins and history shared between them.

Legal use only

Use claude-profile only with Claude accounts you own or are authorized to use, and only in ways your Anthropic plan's terms allow. It does not share, pool or resell access. Don't use it to let other people use your account, or to get around usage limits or other protections.

Quick start

cp claude-profile ~/.local/bin/ && chmod +x ~/.local/bin/claude-profile

claude-profile add work      # creates the claude-work command
claude-work                  # type /login and sign in with the other account
claude-profile doctor work   # checks the two logins are really separate

From then on, claude is your main account and claude-work is the other one. Open them in two terminals and use both at once.

What's shared and what isn't

Shared, and live in bothSeparate per login
Settings, plugins, skills, hooks, CLAUDE.md, MCP servers, project trust, session history: everything in ~/.claude and ~/.claude.json. A change made in one terminal shows up in the other. The login itself, and so the account that inference, usage limits, billing and Remote Control go to.

How it works

claude-work is a small wrapper that runs your normal claude with CLAUDE_SECURESTORAGE_CONFIG_DIR set to ~/.claude-profiles/work. That variable changes only where Claude Code stores the login:

  • macOS: a separate Keychain entry, named Claude Code-credentials- followed by the first 8 hex digits of the SHA-256 of that folder's path.
  • Linux and Windows: ~/.claude-profiles/work/.credentials.json instead of ~/.claude/.credentials.json.

The documented CLAUDE_CONFIG_DIR also gives you a separate login, but it moves settings, plugins and history as well, so the two accounts would stop sharing a setup.

Commands

CommandWhat it does
add <name>Creates claude-<name> in ~/.local/bin and a private folder for its login. It never overwrites a command it didn't create, and the name profile is reserved.
listShows the profiles this tool created.
doctor <name>Checks the Claude Code version, that the variable is supported, that the profile has its own stored login, and that it belongs to a different account from claude.
remove [-y] <name>Deletes claude-<name> and the login stored for that profile. Your main login is never touched.

Set CLAUDE_PROFILES_HOME or CLAUDE_PROFILES_BIN to change where profiles and commands go.

doctor sends each login's access token to api.anthropic.com/api/oauth/profile to find out its email. The token goes to curl on standard input, never on the command line.

Caveats

The variable is undocumented

CLAUDE_SECURESTORAGE_CONFIG_DIR is internal to Claude Code, and a release could rename or drop it. If that happened, /login in a profile would replace your main login. To guard against that, add refuses a Claude Code build that doesn't contain the variable, and removes the new command again if it reports a login before you've signed in to it. Run claude-profile doctor <name> after Claude Code updates.

Tested on macOS only

It has been run on macOS with Claude Code 2.1.330. Linux and Windows support is based on reading Claude Code's source and hasn't been run. The wrapper is a POSIX shell script, so on Windows it needs WSL or Git Bash.

/status may name the other account

/status, and the account email Claude Code gives the model, come from oauthAccount in the shared ~/.claude.json. That names whichever account logged in last. Inference, usage limits and Remote Control use each command's own login and aren't affected. If you use claude-tui-line 0.8.0 or later, its email and organization status-line items show each session's real account.

Removing a profile

claude-profile remove work

This asks for confirmation, then deletes claude-work, that profile's Keychain entry or credentials file, and its folder if it's empty. Add -y to skip the question.
